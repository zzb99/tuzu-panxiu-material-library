# 下载规则说明

## 唯一判断

某条内容存在有效的 `download_file` 关联时，前台显示下载按钮；不存在时不显示。封面图或预览图本身不自动等同于下载附件。

## 用户流程

1. 用户无需注册或登录。
2. 用户无需提交申请。
3. 点击下载不弹确认、授权或营销弹窗。
4. 不创建购物车、订单、支付、发票或会员记录。
5. 不进入审核流程。
6. 点击后由本项目下载接口直接返回文件。

## 接口行为

- 校验内容与附件存在且内容处于已上架状态。
- 读取 `uploads/` 下的受控相对路径，禁止目录穿越。
- 返回正确 MIME、文件长度和安全下载文件名。
- 下载成功请求可使内容下载次数加一，并可写入简化日志。
- 文件不存在或内容已下架时返回明确的 404/不可用响应。

## 多附件

一条内容可配置多个 `download_file`。详情页逐项展示文件名、格式和大小，点击某一项即直接下载；不强制打包，也不弹窗。

## 统计与隐私

只收集运行所需的最小统计信息。若记录 IP，应采用脱敏或哈希方式并设定保留策略，不建立普通用户画像。

## 已实现接口

后台使用 JWT 调用 `POST /api/admin/download-files` 建立资源与已上传 `media_file` 的附件关系；一个资源可建立多条。`PUT /api/admin/download-files/:id` 替换附件，`DELETE` 删除附件，后台查询为 `GET /api/admin/download-files/:type/:resourceId`。

前台先通过详情的 `downloadFiles` 或 `GET /api/download-files/:type/:resourceId` 判断按钮是否显示，再直接访问 `GET /api/downloads/:id`。公开查询与下载都会校验关联资源仍为 `published`；草稿、下架或不存在的资源返回 404。下载服务只接受数据库中 `/uploads/` 下的受控相对路径并阻止目录穿越，不返回服务器绝对路径。

下载接口返回附件 MIME、长度和 UTF-8 安全文件名，并在数据库事务内将 `download_file.download_count` 与对应资源表的 `download_count` 同步加一。未实现且不应实现下载申请、审核、订单、支付或授权申请流程。
