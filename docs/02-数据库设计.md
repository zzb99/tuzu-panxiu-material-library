# 数据库设计

## 1. 范围与运行环境

本阶段仅建设 MySQL 数据库，不包含前台、后台、后端接口或上传逻辑。数据库名称为 `tuzu_panxiu`，脚本面向 MySQL 8.0+，统一使用 `InnoDB`、`utf8mb4` 和 `utf8mb4_unicode_ci`。

- 建表脚本：`database/schema.sql`
- 种子脚本：`database/seed.sql`
- 文件本体：后续存入 `uploads/`，数据库只保存相对 URL、文件类型和大小等元数据。

## 2. 表清单

| 表名 | 用途 |
|---|---|
| `admin_user` | 后台管理员账号，不是普通用户账号 |
| `site_setting` | 网站名称、简介等键值设置，值为 JSON |
| `banner` | 首页 Banner |
| `category` | 各资源类型的分类，支持父子分类 |
| `tag` | 可供后台选择和检索的标签字典 |
| `pattern` | 纹样素材及色彩、工艺、部位、寓意等检索字段 |
| `pattern_image` | 纹样详情多图 |
| `document` | 文献资料 |
| `creation` | 共创作品 |
| `inheritor` | 传承人介绍 |
| `application_case` | 应用案例 |
| `media_file` | 上传文件元数据，覆盖图片、PDF、Word、ZIP、视频等 |
| `download_file` | 资源的直接下载附件 |
| `page_content` | 关于平台、平台简介、页脚等可编辑单页内容 |

共 14 张表。没有普通用户、订单、支付、发票、会员、评论、授权申请、下载申请或下载审核相关表。

## 3. 统一字段约定

五类主要内容表 `pattern`、`document`、`creation`、`inheritor`、`application_case` 均包含：

`id`、`title`、`cover_image`、`description`、`content`、`tags`、`status`、`sort_order`、`is_featured`、`view_count`、`download_count`、`published_at`、`created_at`、`updated_at`。

- 主键统一为 `BIGINT UNSIGNED AUTO_INCREMENT`。
- `status` 统一为 `draft`（草稿）、`published`（上架）、`offline`（下架）。公开查询必须固定附加 `status = 'published'`；后台查询不强制该条件。
- `is_featured` 使用 `TINYINT(1)`，0 为否、1 为是。
- 计数使用 `BIGINT UNSIGNED`，默认 0。
- `tags` 使用 JSON 数组保存标签名称或 slug；`tag` 表作为后台标签字典。接口层应统一输出字符串数组。
- 时间统一使用 `DATETIME`。上架时由后端写入 `published_at`。
- 删除纹样时，关联的纹样图片会级联删除；分类删除时，主要内容上的可空外键置空。

## 4. 重点模型

### 4.1 纹样 `pattern`

除统一字段外，纹样包含 `category_id`、`source_area`、`application_part`、`craft_type`、`main_colors` 和 `meaning`。`main_colors` 必须是 HEX 颜色码 JSON 数组，例如：

```json
["#E60012", "#005CAF"]
```

后端 DTO 应校验每个值符合 `^#[0-9A-Fa-f]{6}$`。`pattern_image` 通过 `pattern_id` 关联纹样并按 `sort_order` 排序。

### 4.2 文献 `document`

支持 `author`、`source`、`year`、`summary`。文献附件不直接塞入该表，而是在 `download_file` 中以 `resource_type = 'document'` 关联。

### 4.3 文件模型

`media_file` 记录所有后台上传文件的通用元数据，`file_type` 支持 `image`、`pdf`、`word`、`zip`、`video`、`audio`、`other`。

`download_file` 是直接下载附件清单：

- `resource_type` 仅支持 `pattern`、`document`、`creation`、`inheritor`、`application_case`。
- `resource_id` 是对应资源 ID。由于它是多态关联，MySQL 无法用单个外键同时指向五张表，完整性由后端事务校验。
- 公开详情存在至少一条 `download_file` 时显示下载按钮；不存在时不显示。
- 点击附件直接请求 `file_url`，不经过登录、申请、审核、订单或支付。

## 5. 索引与查询规则

- 主要内容表均有 `(status, is_featured, sort_order, published_at)` 联合索引，覆盖公开列表、首页推荐和排序。
- 存在分类的内容表均对 `category_id` 建索引。
- `pattern` 额外对 `craft_type`、`application_part`、`source_area` 建索引。
- `download_file` 对 `(resource_type, resource_id)` 建索引。
- 分类对 `(resource_type, status, sort_order)` 建索引。
- JSON 标签和色彩初期由 MySQL JSON 查询完成；数据量增长后可增加生成列或专用关联表，不改变 API 字段格式。
- 关键词初期查询 `title`、`description` 等字段；若数据量明显增长，再评估 FULLTEXT 索引。

## 6. 种子数据

`seed.sql` 包含默认管理员、5 项网站设置、3 条 Banner、9 个分类、20 个标签、8 条纹样及多图、5 条平台自建资料、4 条共创作品、2 条传承人资料、5 条应用方向示例、7 条直接下载附件，以及平台介绍、关于平台、素材使用说明、文化说明和页脚内容。所有资源均为 `published`，封面统一使用 `uploads/placeholders/` 下的本地原创 SVG。

当前版本不创建图库、专题、图案元素、工艺技法模块，也不以其他资源类型伪装这些模块。种子内容中的“示例”“平台自建演示资料”“待补充”均为演示占位资料；基础事实范围和人工替换清单见 `docs/10-初始内容说明.md`。

默认管理员：

- 用户名：`admin`
- 初始密码：`password`
- 哈希算法：bcrypt
- 说明：仅用于本地首次登录联调，后端完成后必须在首次登录立即修改。

种子引用的 SVG 占位图和 TXT 下载说明已放入 `uploads/placeholders/`，可用于数据库、图片静态服务和直接下载联调。它们不代表真实采集素材；正式上线前必须通过后台替换为来源和授权清晰的文件。

## 7. 导入方式

确保本地 MySQL 8.0+ 已启动，在项目根目录执行：

```powershell
mysql -u root -p < database/schema.sql
mysql -u root -p tuzu_panxiu < database/seed.sql
```

若 PowerShell 对 `<` 重定向兼容性不佳，可进入 MySQL 客户端执行：

```sql
SOURCE D:/桌面/tuzu-panxiu-material-library/database/schema.sql;
SOURCE D:/桌面/tuzu-panxiu-material-library/database/seed.sql;
```

`schema.sql` 会删除并重建这 14 张项目表，适用于当前初始化阶段；已有正式数据后不可直接重复执行。`seed.sql` 使用固定 ID，设计为初始化后执行一次。

## 8. 验收查询

```sql
USE tuzu_panxiu;
SHOW TABLES;
SELECT username, status FROM admin_user;
SELECT id, title FROM pattern WHERE status = 'published';
SELECT resource_type, resource_id, file_url FROM download_file;
```

预期 `SHOW TABLES` 返回 14 张表；公开内容查询只返回 `published` 数据。
